# Bilipack 油猴脚本实现方案

本文设计 `apps/monkey` 的工程结构、运行流程和验收方式，以 [产品意图与需求范围](../intent/README.md) 为需求依据。采用 Vite、vite-plugin-monkey、Vue 3 和 TypeScript，生成可直接安装的 `bilipack.user.js`。用户选择视频包后自动校验、上传、填写和核验，最终投稿或保存修改由用户完成。

本计划随已确认的设计持续修订，职责与行为契约见 [架构规范](../architecture/README.md)，上游证据见 [平台核查](../reference/bilibili-upload.md)。实施细节与验收方法在本文维护，执行结果在任务反馈或 PR 中报告；方案调整直接修订相关章节。

## 1. 技术选择与职责

| 部分 | 选择 | 职责 |
| --- | --- | --- |
| 脚本构建 | Vite + vite-plugin-monkey | 开发加载、热更新、元信息和用户脚本产物 |
| 原生入口 | 原生 DOM patch | 上传区点击与拖放、原生入口隐藏恢复及卸载清理 |
| 浮窗 | Vue 3 + Shadow DOM | 独立窗口交互、配置文件代码、附件和核验结果 |
| 样式 | 两侧独立 CSS，通过插件的 `?style` 导入 | 入口样式挂到 document，浮窗样式挂到 Shadow Root，支持开发热更新 |
| 目录读取 | `input[type=file][webkitdirectory]` | 用户一次选择目录，取得文件及相对路径 |
| 配置核心 | `packages/bilipack` + Zod | TOML 语法解析、统一配置 schema、路径规则和推导类型 |
| 页面适配 | `apps/monkey/src/bilibili` | 探测页面、操作原生控件、读取结果 |
| 执行流程 | `apps/monkey/src/workflow` | 顺序执行步骤、处理依赖、收集结果 |

首版验收目标为桌面 Chrome / Edge + Tampermonkey。其他浏览器和脚本管理器在实测后扩展支持范围，不能由插件支持列表推导出 Bilipack 已兼容。

Vue 仅用于 Bilipack 自己的浮窗，不访问 B 站内部 Vue 实例、私有组件状态或 Store。首版通过原生页面控件操作，使用 B 站自己的上传流程；不另行实现上传协议、登录或投稿接口。

插件官方要求放在 Vite 插件列表最后。其类型定义提供 `styleImport`、`build.autoGrant`、`build.metaFileName` 等选项；`?style` 会返回支持热更新的样式节点，适合本方案的 Shadow DOM。[接入说明](https://vite-plugin-monkey.pages.dev/guide/getting-started)、[插件选项源码](https://github.com/lisonge/vite-plugin-monkey/blob/main/vite-plugin-monkey/src/node/utils/types.ts)

## 2. 目录与模块边界

```text
apps/monkey/
├── package.json
├── vite.config.ts
├── tsconfig.json
├── tsconfig.node.json
├── turbo.json
├── src/
│   ├── main.ts                  # 启动、单实例和热更新清理
│   ├── env.d.ts
│   ├── entry/
│   │   ├── port.ts              # 入口定位、呈现与原生视频转发契约
│   │   ├── mount.ts             # 原生上传区入口 patch 与清理
│   │   └── style.css            # 入口专用样式
│   ├── panel/
│   │   ├── mount.ts             # 浮窗宿主、Shadow Root 与 Vue 生命周期
│   │   ├── App.vue              # 订阅 controller，连接用户动作与浮窗
│   │   ├── SelectedDirectoryCard.vue # 标签页装配与当前选择
│   │   ├── UploadDirectoryCard.vue   # 未选择目录时的入口
│   │   ├── components/
│   │   │   ├── summary/        # SummaryTab：总结、待处理项与用户动作
│   │   │   ├── validation/     # ValidationTab：完整结果清单
│   │   │   ├── config/         # ConfigTab：配置原文与空状态
│   │   │   ├── video/          # VideoPreview：播放、字幕轨道和媒体信息
│   │   │   ├── cover/          # CoverPreviews：双比例构图与原图信息
│   │   │   ├── subtitle/       # SubtitlePreview：语言选择与字幕原文
│   │   │   └── ui/             # FloatingPanel、DropdownSelect、CodePreview、MediaMetadata、ResultRow

│   │   ├── utils/               # 媒体信息格式化、高亮和 Shiki CDN 加载
│   │   ├── theme.css            # 浮窗主题变量与按钮规则
│   │   └── style.css            # 浮窗布局与组件样式
│   ├── application/            # controller、协调类型及展示投影
│   ├── input/                  # prepare、types、files、picker、drop、cover
│   ├── workflow/               # compare、plan、run、types、port
│   └── bilibili/               # adapter、context、lifecycle、submission
│                               # fields、tags、cover、subtitles、controls、operation、selectors
└── test/                        # 自有 UI、文件与 mock adapter 流程测试

├── index.ts
├── config/                     # TOML 解析、校验和类型
├── paths.ts                    # 平台无关的相对路径规则
```

`entry/` 和 `panel/` 发起用户操作，`application/controller.ts` 管理导入、页面绑定、终止信号、比对或写入分支、用户重试与资源释放。`application/presentation.ts` 将 Prepared 和结构化结果投影为附件、汇总和应用阶段，协调类型放在 `application/types.ts`。

`input/prepare.ts` 接收是否必须提供视频等明确准备条件，不读页面。配置、文件、字幕和封面准备在 input；视频格式、稿件范围和仅提供定时时间的页面开关检查由 application 调用 `workflow/port.ts` 契约完成，维持改动前预检。页面端口的必要方法为必选，装配和预检直接调用，不以可选调用静默跳过。准备完成后只交出配置原文、解析配置和附件引用，目录索引留在准备阶段。input 不依赖平台、UI 或 controller。

`workflow/compare.ts` 只读比对，`plan.ts` 声明操作和依赖，`run.ts` 执行并核验；PageAdapter、PageContext、Capability、Evidence 和读回错误归入 `workflow/port.ts`。具体 B 站实现放在 bilibili，不反向依赖 application 或 UI。封面与字幕分别建模块，公共 DOM 能力归 controls；原生裁剪拖动换算归 bilibili/cover。

步骤用联合类型限定单步执行或组操作，不通过运行时兜底容忍内部计划缺操作。步骤的 verify 只返回证据；标签漂移由计划显式声明 repair，在 runner 的收敛阶段再次执行并读回，compare 不调用修复。标签收敛以本轮总截止时间、每个目标的有限添加尝试及稳定窗口为界，不叠加独立的总轮数或删除次数上限；多余和重复标签使用同一判定。封面步骤共享声明的组操作与共同重试策略，两个比例分别读回；组固定共同重试，不预留未使用的策略选项；此前跳过或缺失结果的成员也触发整组重试。runner 复用组操作 Promise，按组身份执行一次、共享执行失败并阻断该组其余写入；用户明确重试时整组重新执行，不通过字段前缀或数组位置识别批量操作。

收口方案：平台每次异步操作接收本轮 PageContext 与 AbortSignal，通过内部 Operation 检查身份、代次和目标有效性；表单操作还拒绝投稿等待阶段，等待轮询、异步返回和每次实际控件写入均执行检查，清理不能借机写入新稿件。视频完成等待仅观察原绑定稿件，允许投稿等待，不中断整轮信号。入口呈现与原生视频转发另由 entry/port.ts 定义，main 注入 bilibili 实现，PageAdapter 不承担入口 patch。

计划声明最小步骤策略：重试重新执行、未匹配时等待及依赖放行、投稿等待允许只读核验、等待结果对应的完成证据步骤。runner 只消费策略与关联 ID，不识别视频或编辑表单步骤名称，保持已有顺序、repair 和封面组。输入准备保留校验时读取的字幕原文；展示同步投影已准备数据，不再读文件，不成为执行的异步前置条件。验收使用 mock 操作与通用控件抽象，覆盖长操作中的身份、阶段及终止变化，停止写入与视频等待并存，非固定 ID 的调度和字幕只能读取一次时的执行；不新增 B 站 DOM fixture。交付结果在任务反馈记录，平台事实及未核查范围继续由 reference 维护。

结果语义收口：Step 必须声明 role=target 或 condition，run 原样传入 Result；application 只按分类判断用户目标是否部分完成，不按 ID 排除步骤。空页面视频交接为 target，后续完成观察为 condition，通过 pendingCompletion 更新同一个上传目标，不重复统计视频；已有视频时上传跳过为 condition。字段、字幕和封面比例成员为 target，封面组不另增结果；编辑表单等待为 condition。compare 的字段与附件结果为 target，输入校验与导入异常为 condition；只读匹配仍由应用比对阶段解释为尚未写入。验收覆盖任意 ID、条件成功而目标失败、目标部分完成、两种视频页面状态、完成证据关联、比对及输入错误分类。

实施顺序：先迁移职责与引用，再分离准备及页面检查、展示投影、核验与标签修复、封面组操作，最后同步架构和目录说明。验收覆盖输入独立性、预检失败无写入、verify 无写入、标签最终收敛、封面组失败及用户重试、异步资源与实例隔离；沿用入口和浮窗拆分后的状态。保留显式配置、已有视频不替换、切换中断和失败现场，最终投稿、存草稿与保存修改由用户操作。

`main.ts` 负责创建 adapter 与 controller，分别挂载入口和浮窗、连接页面观察器并统一清理。入口保留 `mountDirectoryEntry` 接口，取消订阅时移除自有节点和样式，恢复原生内容的 visibility 及挂载位置；浮窗卸载 Vue 实例和 Shadow Root 宿主。平台接口由 workflow/port.ts 定义，application 组合 input 与 workflow；结果通过返回值和回调向上传递，不通过底层反向导入上层模块。

入口样式只包含原生上传区选择器，浮窗主题只包含 Shadow Root 内的规则，两侧分别保留需要的颜色变量与按钮声明，不建立跨目录样式导入。`panel/labels.ts` 负责字段、动作及状态文案映射；`panel/utils/` 包含 `media-metadata.ts`、`highlight.ts` 和 `shiki-cdn.ts`。`plugins/native-shiki-import.ts` 识别 `/src/panel/utils/shiki-cdn.ts`，保留构建产物中的原生动态导入。路径调整需同步组件、测试导入和样式 mock。

代码组织调整保持现有用户行为及平台支持范围，文案映射在 panel/labels.ts，颜色与 loading 在 panel 内。

目录卡片位于 `panel/`，与 `App.vue` 同层，负责选择状态与标签页装配。浮窗内容组件在 `components/` 中按标签页分目录。`SelectedDirectoryCard` 保留标签页切换、键盘导航和选中字幕语言，从中提取总结、校验、配置的内容组件；视频、封面、字幕预览归入各自目录。多处可用的展示与控件放入 `components/ui/`，供标签页和浮窗装配复用。总结页继续向目录卡片发出 `write`、`clear`，再由上层连接 controller。提取时保持原有 tabpanel 容器、DOM 顺序、v-show 状态保留、视频按活动标签页挂载及资源清理行为；同步组件和测试导入路径。

目录按钮点击后，controller 在同一用户手势调用链中同步触发 `input/picker.ts` 的原生选择器，再异步等待选择结果，不能先执行异步预检而丢失用户激活。应用通过包导出引用 `bilipack`，不跨目录引用库源码。

库只接收文本、配置对象和文件描述信息，不依赖 `window`、DOM、Node.js 文件系统或 GM API。浏览器 `File` 对象保留在应用内，避免把脚本运行环境带进配置规范。

内部素材只使用已校验、已准备的契约，不保留旧结构兼容：CoverImage 必须带原图来源，单图来源必须带裁剪位置；平台上传使用 source.file，预览文件不成为缺少原图时的备用上传输入。Attachment 按视频、封面、字幕区分必需数据，UI 在目录卡片处分组后传给相应组件。配置及文件错误在输入边界处理，页面可用性、身份变化和控件状态在平台边界处理，不在中间层再次模拟输入校验。

页面绑定使用 workflow/port.ts 的 matchesContext；controller、执行器和平台 Operation 共用身份、代次及数量规则。空白页出现首个视频是允许的状态推进，已有视频消失或多 P 则失效。比对正常返回后进入待写入，能力不足仍按目标跳过，不增加不可达的整轮阻断分支。验收覆盖单图来源及位置、三类附件展示、视频消失与多 P 中断、导入取消与卸载释放。

## 3. 工程接入

`apps/monkey/package.json` 使用包名 `@bilipack/monkey`，设置 `private: true`。运行依赖包括 `bilipack: workspace:*` 和 Vue；开发依赖在应用中显式声明 Vite、vite-plugin-monkey、`@vitejs/plugin-vue`、`vue-tsc` 和测试工具，版本与仓库工具链协调。TOML 解析器归属 `bilipack`，选型条件为浏览器兼容、保留带时区时间语义、无 Node.js 内置依赖，并用需求示例验证。

Vite 配置草案如下；这里的域名匹配是启动范围，实际执行还必须通过页面探测：

```ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import monkey from 'vite-plugin-monkey';
import pkg from './package.json';

export default defineConfig({
  plugins: [
    vue(),
    monkey({
      entry: 'src/main.ts',
      userscript: {
        name: 'Bilipack',
        namespace: 'https://github.com/yjl9903/bilipack',
        version: pkg.version,
        description: '从视频包填写 B 站投稿信息并核验结果',
        match: ['https://member.bilibili.com/*'],
        'run-at': 'document-idle',
        noframes: true,
      },
      server: { prefix: 'dev: ', mountGmApi: false },
      build: {
        fileName: 'bilipack.user.js',
        metaFileName: true,
        autoGrant: true,
        systemjs: 'inline',
      },
    }),
  ],
});
```

构建将 Vue 和 diff 配置为 `externalGlobals`，版本随锁定依赖生成 `@require`；Shiki 按固定版本通过原生动态 import 按需加载，加载失败保留纯文本预览。配置草案只表达基础接入，完整插件与依赖配置以 `vite.config.ts` 为准；`native-shiki-import.ts` 在构建时保留 Shiki 原生导入，产物检查拒绝残留 SystemJS loader、占位 marker 或内联 Shiki runtime。

不预填 `@connect *` 或无需使用的 GM 权限。需要 GM API 时从 `$` 显式导入，并检查产物里的 `@grant`。不把 GM API 挂到宿主页面。只有实测证实需要宿主窗口对象时才引入 `unsafeWindow`，并把调用封装在适配层。[GM API 文档](https://vite-plugin-monkey.pages.dev/guide/gm-api)

`env.d.ts` 引用 `vite/client`、`vite-plugin-monkey/client` 和 `vite-plugin-monkey/style`。应用 TypeScript 配置补充 `DOM`、`DOM.Iterable`，包含 `.vue`、`.ts` 文件；Vite 配置使用独立的 Node.js TypeScript 配置。应用类型检查同时覆盖 Vue 代码和构建配置。

| 文件 | 实现时的调整 |
| --- | --- |
| `pnpm-workspace.yaml` | 增加 `apps/*` |
| 应用 `package.json` | `dev: vite`、`build: vite build`、`preview: vite preview`、`typecheck: vue-tsc --noEmit && tsc --noEmit -p tsconfig.node.json`、`test:ci: vitest run` |
| 库 `package.json` | 保留 tsdown 构建；增加 `dev: tsdown --watch`，供应用开发读取更新后的导出 |
| 根 `package.json` | `dev` 改为 `turbo run dev`，由任务图调度；版本脚本纳入 `apps/monkey/package.json` |
| 根 `turbo.json` | 保留 `build.dependsOn: ["^build"]` 与 `dist/**`；类型检查和测试的输入改用 `$TURBO_DEFAULT$` 并纳入根 TS 配置，覆盖 Vue、CSS、配置和自有测试 |
| 应用 `turbo.json` | 继承根配置；`dev` 设置 `dependsOn: ["^build"]`、`with: ["bilipack#dev"]`、`persistent: true`、`cache: false`；`preview` 不缓存并常驻 |
| 库开发任务 | 标记常驻、不缓存；不得把常驻 watch 任务作为 `dependsOn` 的前置任务 |
| `.github/workflows/ci.yml` | 现有根构建和测试覆盖新应用；增加用户脚本产物检查，并保存可供安装验收的构建附件 |
| `.github/workflows/release.yml` | 库继续发布 npm；私有应用不发布 npm，将 `.user.js` 和 `.meta.js` 附加到对应 GitHub Release |

开发入口使用 `pnpm exec turbo run dev --filter=@bilipack/monkey`，先生成库产物，再同时启动库 watch 和 Vite。确认库产物变化会触发应用更新，必要时将 workspace 库排除于 Vite 依赖预打包。正式构建使用根 `build` 任务，发布产物为 `apps/monkey/dist/bilipack.user.js` 和 `.meta.js`。

开发脚本与正式脚本不要同时启用。`downloadURL` / `updateURL` 指向仓库 Release 中对应的用户脚本与元信息产物，构建检查其唯一性和一致性；首版仍需验收手动安装构建产物。接入时锁定插件实际安装版本，并验证其与仓库 Vite 8 和 TypeScript 工具链的组合，不以 GitHub main 的类型定义代替安装版本验证。

## 4. 页面生命周期与浮窗

脚本在 `member.bilibili.com` 顶层页面启动轻量探测器。URL 只是候选条件，还需确认投稿表单、视频区域和稿件上下文。非目标页面不显示操作入口，不执行表单修改。

空白投稿页由 `entry/mount.ts` 覆盖原生上传区域，保留「上传视频」与「上传 Bilipack 目录」按钮，并处理视频或目录拖放。原生内容保持挂载但隐藏，供适配器转发视频操作；离开目标区域或卸载时恢复。已有视频和编辑页从浮窗导入。浮窗独立挂在 Shadow Root 内，样式由 `panel/style.css?style` 挂入，不与原生入口共用样式节点。

浮窗包含目录入口、配置文件代码、附件信息、两种比例封面预览和结果清单。展示 controller 提供的当前步骤和状态，运行时提供忙碌指示，收起后仍显示活动状态；不从动画或进度推断上传完成。运行中禁用重复导入，允许折叠浮窗；不提供停止按钮、任务队列或任务管理页。上传进度由 B 站原生页面展示。

配置详情只渲染用户导入的原始 `bilipack.toml`，使用只读代码块和 TOML 语法高亮，保留注释、字段顺序、空行及原始值。配置文本独立保存在本次导入上下文中，不从解析后的对象重新序列化，也不补入默认字段。即使解析或校验失败，也能查看原文；错误信息在代码块之外展示。不将配置字段转换成表单、卡片、键值列表或其他专用配置 UI，不提供在线编辑。附件预览与结果清单保持独立。

使用路由事件、局部 `MutationObserver` 和低频 URL 检查识别 SPA 切换；观察范围尽量限制在候选表单区域。不要只依赖首次 `document-idle` 或把全站 DOM 变化逐次触发为完整扫描。

每次执行绑定稿件身份和页面代次。跨稿件切换、离开表单或宿主控件失效后，中止后续操作并报告中断；同一新投稿从上传页进入表单属于预期变化，需要用视频与稿件上下文关联，而非仅按 URL 变化判断。无法确认仍为同一稿件时停止推进。

挂载、监听和观察器必须可清理；HMR dispose 卸载旧实例，避免重复入口和重复事件。执行中发生代码热更新时结束本轮调度并提示重新检查，不能自动重放上传。内部使用 `AbortController` 清理等待和监听，这不等于提供停止按钮，也不取消 B 站已经开始的上传。

## 5. 目录读取与配置校验

目录入口的用户点击直接触发文件选择。采用 `webkitdirectory` 获取 `FileList`，依据 `webkitRelativePath` 去掉共同的所选根目录，建立相对路径索引。浏览器提供的是用户选中的文件对象，不是可任意读取磁盘的绝对路径。[目录选择 API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)

视频保持为 `File` 引用，不读成 ArrayBuffer 或 Base64。只读取配置和实际需要的字幕文本、解码封面；临时 Object URL 在替换或清理时释放。取消目录选择返回空闲状态。

配置定义集中在 `packages/bilipack/src/config/schema.ts`：采用 Zod 严格对象、字段转换与组合校验，作为结构和校验的唯一来源；`types.ts` 使用 `z.infer` 推导 `Config` 和 `Position`，继续从它们推导字段目标。`parse.ts` 保留 TOML 语法处理、裸日期预检、Zod issue 到中文诊断的适配及成功结果递归冻结，不另存字段种类表或配置结构。schema 不接收页面状态，不以适配器能力限制配置范围。按根声明的 pnpm 版本为库添加 Zod 运行时依赖并更新锁文件；API 依据 [Zod 官方文档](https://zod.dev/api)。

迁移验收沿用公开 `parseConfig` API：覆盖需求示例、全部区块的未知字段、字段类型和组合错误、路径规范化、单图默认值及双图互斥、标签和字幕语言重复、日期时区与日历边界、显式值与省略、中文诊断路径及分类、嵌套数据冻结；同时运行 workspace 类型检查、测试和构建，确认应用消费的类型和用户脚本产物可用。

修改页面前完成以下校验，错误汇总到字段路径：

1. 所选根目录有且只有一个入口 `bilipack.toml`，不自动搜索并选用子目录配置。
2. 解析 TOML，校验已知区块、字段类型、枚举和组合；未知字段报错，避免拼写错误被静默忽略。
3. 路径统一使用 `/`，拒绝绝对路径、盘符、URL 和 `..` 越界引用；不进行大小写模糊匹配或文件名猜测。规范化后有冲突时报告冲突。
4. 检查实际步骤需要的文件存在、非空且类型可处理；封面可解码，字幕为有效 SRT。文件大小和图片尺寸限制根据实测页面能力维护，不凭经验写死平台阈值。
5. 视频为 `absent` 时必须提供 `video.file`；视频状态未知时不把它当成空白页面。已有视频一律跳过上传，包内的视频不作为此次执行必需附件。
6. 单图和双图模式字段不混用，位置为两个 `0..100` 数值；同语言字幕重复配置报错。
7. `scheduled=true` 必须有带时区的时间；`scheduled=false` 同时提供 `at` 视为冲突；只提供 `at` 时要求页面已启用定时，否则报配置与页面状态冲突。原生 TOML 日期和日期字符串均拒绝日历或时分秒越界，不允许 Date 自动滚到次日。统一比较时间点，不丢失原时区语义；平台可选时间范围仍需页面核验。
8. 已能确定账号无权使用或当前页面不支持的显式配置，在改动前报告。上传完成前尚不能探测的能力记为待检查，并在相应步骤前再次检查。

配置必须保留“字段是否存在”。`false`、空字符串和空数组都是显式值，不使用 truthy 判断。只在用户提供封面区块时应用 `mode=single`、位置居中的默认值；不得给未配置的布尔开关填默认值。

建议明确以下集合语义：`info.tags` 为目标标签列表，空数组表示清空；字幕按语言添加或更新，空列表表示没有字幕操作，未列出的语言保留。文本空字符串表示清空；是否允许由字段校验和页面结果决定，不能静默替换成旧值。

## 6. 执行流程与结果模型

采用轻量执行器处理本次导入，不引入通用任务平台。导入通过输入校验后绑定稿件身份、页面代次、适配器和终止信号；已有视频先只读比对，用户点击「写入配置」后才修改页面，空白页直接进入执行。已有视频的确认交互与 [intent §3.2](../intent/README.md#32-在已有视频的页面补充或更新内容) 的直接填写描述仍有差异，验收分别说明比对与实际写入，不以当前实现改写需求。

```text
选择目录 → 校验与准备 → 绑定页面上下文
    ├─ 已有视频：只读比对 → 用户确认写入 ─┐
    └─ 空白页：准备上传 ──────────────────┤
                                         ↓
上传或跳过上传 → 等待表单可用 → 常规字段 → 封面 → 标签 → 字幕
    → 交还页面并只读等待视频完成 → 展示结果 → 用户检查并提交
```

视频状态区分空白、上传中、完成、失败和未知。已有视频不重新上传；上传中沿用并等待，失败或未知状态报告原因。检测到多 P 时报告超出单视频范围。

表单就绪后填写可与原生视频上传重叠，DOM 写入仍串行调度，避免弹窗相互干扰；视频完成是准备完成的必要条件。表单操作结束后进入统一 observe 阶段，界面显示视频等待并交还页面；无论用户是否进入平台投稿等待页，均只观察视频、不再调度写入或修复，观察结束后统一汇总结果。验收覆盖等待期间用户修改表单或进入平台等待页，不重新读回或覆盖用户修改。标签放在常规字段及封面之后，减少联动和异步推荐覆盖，再处理字幕。验收覆盖表单可用但视频仍上传的情况，不要求等上传完成才开始填写。

真实接口以 [任务执行与核验](../architecture/workflow.md) 和 `workflow/types.ts` 为依据：`RunContext` 由 `Prepared`、`PageContext`、`PageAdapter` 与 `AbortSignal` 组成；`plan` 返回 `Step[]`，步骤声明 `id`、`dependsOn`、可选跳过原因及能力条件，分别提供 `execute` 或 `group.execute` 与 `verify`，标签另声明 `repair`。`verify` 返回 `Evidence`，执行器转换为同 `id` 的 `Result`，而非让步骤直接生成结果状态。进度通过执行器回调反馈，不放入 `RunContext`。

验收需要证明操作返回与核验通过分离：只读字段匹配不表示执行过写入；本地附件与现有附件不能仅凭名称判定一致；视频交给控件后仍需独立等待完成。每个未完成结果保留期望、实际值或原因。

未配置字段不生成修改步骤；已有视频产生明确的跳过上传说明。分区、声明、定时开关等可能影响其他字段，先执行这些控制项，再查找依赖控件。适配器记录已知联动关系，执行前读取可能受影响的未配置字段；若联动改变了它们，能安全恢复则恢复并核验，否则报告冲突。

失败处理规则：

- 输入校验失败：不修改页面。
- 视频上传、页面身份等基础条件失败：阻断依赖步骤。
- 单个字段失败：仅在页面上下文仍可靠、弹窗已安全退出时继续独立步骤；无法恢复稳定上下文则结束执行。
- 未确认成功的附件不能自动重传，避免重复上传；读取和等待可以有限重试，幂等字段操作先读后决定是否重试。
- 所有等待有截止时间并清理监听。视频使用较长总截止时间和无进展检测，普通控件使用较短等待；阈值在页面实测后确定。

每个步骤执行后核验，等待视频完成后直接汇总，不再统一读回或修复此前已核验的目标；后续平台异步变化由用户检查。核验结果分为“准备完成”“部分完成”“未执行或执行中断”；存在 `failed`、`blocked`、`unverified` 时绝不能显示全部完成。

平台必填但用户未配置的内容单独显示为“仍需补充”，不擅自生成默认值。结果同时表达本次目标是否完成和是否仍有平台提示，不使用“可以直接投稿”的承诺。

## 7. B 站页面适配

每类控件提供 `probe / read / apply / verify` 行为，定位优先使用字段标签、语义属性和局部容器；稳定属性作为后备，避免依赖位置索引和易变化的哈希类名。每次操作重新定位并要求唯一匹配，不能拿到第一个同名按钮就点击。

| 字段组 | 处理方式与核验 |
| --- | --- |
| 标题、简介、粉丝动态 | 文本框使用对应原生 setter 和控件所需事件；富文本单独适配。只规范化换行等表示差异，保留正文语义 |
| 声明、分区、可见范围 | 按配置显示名定位唯一选项；出现重名、层级不明或不可用时报错，不模糊猜选 |
| 标签与话题 | 分开操作与读取；标签收敛到配置目标列表，话题核验页面选中的目标 |
| 已有合集 | 在当前账号可选合集里精确匹配名称；不创建合集，重名时报告歧义 |
| 禁止转载、水印、空间隐藏、商业信息、音视频、互动开关 | 先读当前状态，仅在不一致时操作；检查禁用状态与原因，随后读回。开关开启后若还需必填材料则报告未完成 |
| 定时发布 | 先设置开关，再按控件时区填写时间并比较实际时间点；编辑页不支持修改时明确报告 |

适配器只暴露具体操作，不提供按任意文字点击页面按钮的公共入口。最终“投稿”“发布”“保存稿件修改”不属于可执行步骤。局部封面确认等按钮需要核实作用范围；如果某入口实际会提交整条稿件，则不得自动调用。

上传优先定位原生文件 input，用 `DataTransfer` 构造 FileList，赋给 `input.files`，再触发控件需要的事件。这个方案必须在真实油猴环境验证：脚本派发的事件不是可信用户事件，页面可能不接受；不能把 DOM 赋值成功当作上传成功。[事件可信性说明](https://developer.mozilla.org/en-US/docs/Web/API/Event/isTrusted)

视频必须读取页面明确的上传完成状态；进度 100%、文件名出现或提交按钮可点击都不足以单独证明成功。继续保留页面原上传控件供用户接手。

## 8. 封面与字幕

### 封面

单图模式将一张原图交给原生封面编辑器，开启双比例同步改动，分别设置 16:9 和 4:3 裁剪位置；不能把本地裁剪图当作两张独立图片上传。本地目标预览与原生裁剪使用同一位置语义：

```text
cropW = min(W, H * r)
cropH = cropW / r
x = (W - cropW) * horizontal / 100
y = (H - cropH) * vertical / 100
```

`W × H` 为原图尺寸，`r` 为目标比例；位置映射到最大内接裁剪框的可移动范围。某轴无裁剪余量时该轴位置不影响构图。画布就绪以非透明像素判断，不将纯黑图像当作空画布。验收覆盖纯黑素材、居中、两端和任意偏移，并分别检查两个比例，不以预览成功代替平台核验。

双图模式关闭同步，分别使用两个原图设置对应槽位，在同一编辑器中作为一组局部确认，避免分别保存造成相互覆盖。当前输入校验要求图片符合对应比例，不静默二次裁剪。部分失败后的重试按组处理。

[封面核查](../reference/bilibili-upload.md#封面编辑器) 已覆盖新投稿和已发布编辑表单的同步裁剪、独立双图及重开读回。实现与验收使用原生编辑器的局部确认和重开核验；画布、裁剪几何及同步状态只能证明当前表单状态，不证明逐像素一致、最终保存或公开展示。结果需保留这一边界，最终提交仍由用户完成。

### 字幕

预检 SRT 的基本结构、时间顺序和范围，保留原文。按语言组织独立步骤，未配置语言保持原状。当前已接入中文新投稿字幕；[字幕核查](../reference/bilibili-upload.md#字幕入口与更新语义) 已确认入口支持 SRT，中文新增、删除后替换、局部确认及重开读回可操作。同语言更新采用移除旧项再添加，不能在语言不可重复选择时直接重复新增。

语言与页面选项精确映射，禁止模糊猜测。验收覆盖新增及替换，读回语言和文件名，并明确不能由这些属性证明正文一致或最终保存。局部确认按钮的作用范围已经按新投稿核查记录限定，不自动调用最终投稿。

未接入能力直接纳入以下接入与验收范围：

- **其他语言**：先核查可选语言及新增、移除、替换、局部确认和重开行为；补充明确语言映射及适配，再以对应语言 SRT 验收新增与更新。未核查语言不能仅因中文路径可用而放行。
- **已发布编辑页**：核查字幕入口、页面切换及保存作用范围，不能从新投稿推断编辑页行为。依据 [intent §4.6](../intent/README.md#46-字幕) 的逐份上传与核验要求设计接入，并验证新增、更新及返回当前稿件的流程；任何额外提交或发布动作仍须由用户完成，不绕开最终人工提交边界。
- **能力不足的处理**：当前对未接入语言及已发布字幕按单项跳过，继续其他受支持目标。结果明确列出未完成字幕及原因，不能将跳过算成上传完成；验收覆盖逐份反馈和部分完成汇总。补齐能力须有对应核查、适配及验证，单项跳过是未完成反馈，不代替逐份上传与核验需求。

配置范围由用户意图定义；上游限制保留为接入依据和验收边界，不据此缩减 intent。

## 9. 验证与验收

| 层次 | 必须覆盖的行为 |
| --- | --- |
| 配置与文件单测 | 需求中的 TOML 示例、未知字段、缺附件、路径越界、`false` 与省略的区别、空值、时区、字幕语言冲突、裁剪位置 |
| 执行器单测 | 已有视频绝不上传、基础失败阻断依赖、独立失败继续条件、路由切换中断、附件不盲目重试、部分失败不报全部成功 |
| 交互与适配契约测试 | 通过 mock adapter 验证延迟、失败与清理；自有 UI 用 jsdom 测试，不建立源站 DOM fixtures 或依赖其结构的自动化测试 |
| 产物检查 | `.user.js` 头部、版本、match、grant、`.meta.js` 一致性；无 localhost、开发客户端、Node.js 内置模块或未预期远程资源 |
| 真实脚本验收 | Tampermonkey 安装构建产物，分别验证空白投稿、已有视频未提交表单、已发布稿件编辑页 |

代码组织验收使用 Node.js >=24 和仓库声明的 pnpm，运行适用现有测试、`pnpm typecheck`、`pnpm build`、`pnpm test:ci`。核对入口点击与拖放、原生视频转发、busy 防重入、隐藏与恢复、浮窗显隐、预览、结果文案及高亮降级。检查旧路径引用、entry/panel 相互导入、样式声明与顺序、文档链接及 `git diff --check`，保持无关工作区修改。通过标准是两侧独立挂载与清理、现有测试及构建检查通过、用户可观察行为保持现状。

真实页面复核还需覆盖空白上传区视觉与点击、视频和目录拖放、进入编辑页后的浮窗及卸载后的原生入口恢复。本地测试、开发脚本与正式安装验证分别报告，未核查项不得推断为通过。

真实验收使用专用测试素材，覆盖双比例封面、多语言字幕、定时开关、页面无权限和上传失败；停止在用户最终检查处。开发模式和构建产物都要测试，Vite 页面或模拟 DOM 通过不能代替油猴作用域、CSP 和实际上传验证。

全程记录“目标值、实际值、失败原因”，附件仅记录相对路径和大小等必要信息。文件内容和页面登录信息不持久化。首版状态仅在内存中保存，刷新后不会自动恢复或继续操作。

验收还需检查没有配置的字段、封面、视频和字幕语言保持原状；页面联动导致无法保持时，结果必须明确显示冲突。失败后原有填写与上传现场可供人工接手。

浮窗验收覆盖当前步骤、忙碌状态、展开收起、拖动缩放及监听清理；配置详情仅展示原始 TOML 代码，注释和原始值完整保留，错误配置也可查看。配置内容按文本安全渲染，语法高亮不得将用户内容作为 HTML 执行。

## 10. 实施依赖与补充核查

| 实施项 | 依赖与方案 | 验收条件 |
| --- | --- | --- |
| 工程与入口装配 | 维护 workspace 构建、独立入口及浮窗挂载 | 正式脚本可安装，切换与卸载恢复原生入口，不重复监听 |
| 视频包预检 | 领域解析与应用文件索引先于页面操作 | 需求示例可解析，显式值保留，错误输入不修改页面 |
| 比对与执行编排 | 已有视频只读比对；写入步骤依赖表单条件 | 未确认写入前不改页面，表单填写与视频等待正确衔接 |
| 字段与附件适配 | 依据目标及核查证据扩展能力，逐份反馈字幕完成情况 | 每项保留目标、实际值和原因；未配置项保持，失败可接手 |
| 产物与安装验证 | 类型、mock 流程、构建产物检查后做真实脚本复核 | 三类起点分别报告验证范围，最终提交留给用户 |

平台核查已有结论直接用于方案，不重新把已验证路径列为未知问题。新增能力或平台变化时补充确认：

- 页面识别、稿件身份及原生上传完成信号是否仍成立，正式脚本与开发模式是否一致。
- 封面同步、两比例局部确认及重开核验是否仍符合 reference；最终保存继续由用户检查。
- 未接入字幕语言及已发布页面如何新增、更新并核验，是否存在需要用户完成的额外提交动作。
- 未核查的字段开启状态、定时时间、权限及联动如何接入并核验，而不是仅确认关闭状态。

新增结论写回 reference，更新对应接入方案及验收范围。未实现和未核查能力明确保留边界，不把人工处理提示当作功能已交付。

## MVP 逻辑清理

字段目标由 Config 推导为字段和值关联的联合类型，配置解析负责输入类型校验，平台适配只检查原生控件状态及页面限制，不重复校验内部目标类型。入口挂载必须显式注入原生视频转发与呈现回调，不用空函数隐藏装配缺失。PageContext 明确提供 editor，浮窗直接消费页面识别结果，不从视频数量兜底推断编辑表单。

视频完成观察依赖视频交接，不依赖编辑表单就绪；表单等待失败或用户提前进入投稿等待时，同一稿件的视频仍需独立核验。上传前的实时视频存在性检查集中在平台上传边界，不在计划层重复探测。身份绑定、写入前检查和终止信号继续保留。

字幕语言归一由字幕预览组件维护，通过 v-model 与目录卡片共享，卡片不再维护同一份归一逻辑。验收覆盖字幕列表变化后视频预览使用的新语言，以及表单就绪失败后视频完成与未执行字段分别反馈。同步类型、架构说明，并运行构建、类型检查及全部本地测试；真实平台验证仍单独报告。

本轮审查仍需单独推进的需求差异：已有视频导入目前先比对、等待用户确认写入，与 intent 的直接填写描述不同；本次不改变既有交互。平台适配目前只对显式标签目标收敛，尚未实现分区、声明或互动开关联动前后对未配置字段的完整快照、恢复及冲突报告。该项需补充具体联动证据与 mock 契约，再接入恢复；现有字段读回通过不能证明未配置内容全部保持原状。
