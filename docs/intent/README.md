# Bilipack 产品意图与需求范围

本文定义 Bilipack 的产品定位、首版需求范围、用户使用故事、用户直接编写的配置格式和预期行为。

## 1. 产品定位

Bilipack 是面向 UP 主的通用 B 站投稿辅助工具。

用户将已经准备好的视频、封面、字幕和投稿信息组织为一个视频包，在 B 站原生页面选择该目录后，由 Bilipack 油猴脚本自动上传附件、填写表单并核验结果。最后由用户检查并自行提交。

核心目标是减少重复选择文件、填写信息和检查遗漏的操作，让手工准备或由上游工具生成的内容能够按统一规范导入 B 站。

## 2. 产品职责与边界

### 2.1 产品组成

| 组成 | 职责 |
| --- | --- |
| 视频包规范 | 定义目录组织方式、配置文件结构和附件引用方式，供用户及上游工具准备视频包 |
| 油猴脚本 | 在 B 站页面提供入口和浮窗，读取视频包，执行上传、填写和核验，反馈结果 |

### 2.2 与用户、上游工具的分工

- **用户或上游工具**：准备素材和投稿信息，按规范生成视频包。
- **Bilipack**：读取并校验视频包，在 B 站原生页面执行本次稿件的自动化操作。
- **用户**：检查最终结果，亲自投稿或保存稿件修改；自动化失败时可接手处理。

Bilipack 不绑定特定节目、目录生成工具或内容制作流程。节目专属的标题、标签、署名和投稿偏好由输入配置表达，不作为通用工具的固定默认值。

### 2.3 首版范围

首版聚焦单条稿件、单个视频的表单自动化：

- 定义视频包目录和 TOML 配置规范。
- 一次选择目录，读取配置和所需附件。
- 根据页面状态上传视频，或跳过视频上传。
- 按配置填写投稿信息和设置，上传封面及字幕。
- 覆盖常规文本、选择项和开关，包括发布、展示、互动及音视频设置，具体范围见第 4.5 节。
- 展示本次配置和执行结果，核验页面实际状态。
- 支持从空白投稿页、已有视频的未提交表单和已发布稿件的编辑页开始。

首版不包含：

- 视频、封面、字幕制作，以及文案或节目模板生成。
- 多 P、批量投稿、任务队列及额外任务系统。
- 个性化卡片配置和章节管理。
- 必火推广等独立推广服务的购买与投放操作。
- 自动点击最终投稿按钮，或自动提交已发布稿件的修改。
- 停止按钮。
- 特定上游工具的数据处理逻辑或 CUA 操作流程。

## 3. 用户使用故事

### 3.1 从空白投稿页准备新稿件

**作为已经准备好素材和文案的 UP 主，我希望选一次视频包目录，就能完成投稿准备，最后由我检查并提交。**

1. 用户打开尚未选择视频的 B 站投稿页。
2. 点击「使用 Bilipack 目录投稿」入口，选择视频包目录。
3. Bilipack 读取并校验配置和引用文件；此时包内必须提供视频。
4. 校验通过后，Bilipack 自动上传视频，并在后续表单可操作时填写配置项、处理封面和字幕。
5. 用户通过浮窗查看本次配置和附件。
6. Bilipack 核验实际结果，在页面提示完成或列出未完成项。
7. 用户检查 B 站原生表单，亲自点击投稿。

选择目录后直接进入校验和自动化流程，不要求用户逐个重新选择附件。

### 3.2 在已有视频的页面补充或更新内容

**作为已经上传视频或正在编辑已发布稿件的 UP 主，我希望导入配置和附件来补充、更新表单，而不必重新上传视频。**

1. 用户进入已有视频的页面，可以是未提交的投稿表单，也可以是已发布稿件的编辑页。
2. 从 Bilipack 浮窗中的入口选择视频包目录。
3. Bilipack 根据页面实际状态识别已有视频，跳过视频上传；视频包允许省略视频文件及其配置。
4. 校验通过后，按显式配置填写字段、处理附件，未配置的项目保持页面原状。
5. Bilipack 核验结果并提示，用户检查后自行投稿或保存修改。

用户不需要手动选择“新投稿”或“编辑稿件”模式。页面已有视频时，即使视频包包含视频，也跳过视频上传。

### 3.3 校验或执行失败后继续处理

**作为使用自动填写的 UP 主，我希望知道哪些内容没有完成，并能利用页面上的已有结果继续操作。**

- 配置或文件校验失败时，在改动页面前提示具体问题。
- 执行过程中出现失败时，保留已填写内容和已有上传状态，明确展示失败项或需要人工处理的内容。
- 用户可以在当前页面接手处理，无须因 Bilipack 失败而从头开始。
- 部分失败不能被报告为全部完成。

## 4. 视频包与配置约定

视频包由配置文件和本次操作所需的素材组成。本节定义用户可以配置的内容、对应字段名和配置示例。

### 4.1 目录与配置入口

- 视频包是用户选择的一个目录。
- 根目录固定使用 `bilipack.toml` 作为配置入口。
- 配置采用 TOML，便于人类阅读、编辑及添加注释。
- 附件使用相对于配置文件所在目录的路径引用。
- 附件文件名和子目录可以自由安排，不依赖固定附件名称。

示意目录如下，附件名称仅为示例，不代表必需文件清单：

```text
某个视频包/
├── bilipack.toml
├── video.mp4
├── cover.jpg
└── subtitles/
    ├── zh.srt
    └── en.srt
```

配置按以下区块组织：

| 区块 | 用途 |
| --- | --- |
| `[video]` | 视频文件 |
| `[cover]` | 封面文件、模式及裁剪位置 |
| `[info]` | 标题、声明、分区、标签、话题及简介 |
| `[publish]` | 定时发布及所属合集 |
| `[display]` | 水印、可见范围及个人空间展示 |
| `[commercial]` | 商业推广信息 |
| `[media]` | 音效、音质及全景视频 |
| `[interaction]` | 粉丝动态及评论、弹幕设置 |
| `[[subtitles]]` | 字幕列表，每项指定一份文件及其语言 |

用户按需选择区块和字段，无须填写完整配置；示例见第 4.7 节。

### 4.2 配置使用意图

- **按需提供内容**：用户只需配置本次希望填写或更新的内容，无须准备一份完整表单。仅从空白投稿页开始时必须提供视频。
- **保留已有内容**：未配置的项目保持页面原状，用户可以只更新某一部分内容。
- **忠实表达用户意图**：填写结果应符合用户提供的内容和设置，不擅自改写文案、增加标签或加入话题。
- **明确告知未完成事项**：如果缺少平台要求的信息，或受页面、稿件状态及账号权限限制而无法完成，应告知用户具体事项，方便补充或接手。

### 4.3 视频

- 首版只处理单个视频，不支持多 P。
- 页面没有视频时，视频包必须提供视频，由 Bilipack 上传后进入后续流程。
- 页面已有视频时，可以省略视频文件及其配置；即使包内提供视频，也跳过视频上传，不替换页面已有视频。

| 配置字段 | 用途 |
| --- | --- |
| `video.file` | 指定视频文件的相对路径 |

### 4.4 封面

封面支持两种素材来源模式：

1. **默认模式：单张封面 + 调整位置。** 用户准备一张图片，用于 16:9 和 4:3 两种展示比例，并能够分别调整裁剪位置，使主体和文字出现在合适的位置，无须预先制作两张图片。
2. **独立双封面模式：分别提供两张图片。** 用户分别准备 16:9 和 4:3 封面，各自应用于对应比例，互不覆盖，满足独立构图需求。

两种模式遵循相同的结果要求：

- 配置封面后，按所选模式处理两种比例，包括编辑已有稿件时的封面更新。
- 用户能够检查两种比例的最终构图。
- 未配置封面时，保持页面原有封面不变。

| 配置字段 | 用途 |
| --- | --- |
| `cover.mode` | 选择单图 `"single"` 或双图 `"dual"`，默认单图 |
| `cover.file` | 单图模式使用的封面文件 |
| `cover.wide_position` | 单图模式的个人空间封面（16:9）裁剪位置百分比，默认居中 |
| `cover.standard_position` | 单图模式的首页推荐封面（4:3）裁剪位置百分比，默认居中 |
| `cover.wide_file` | 双图模式的个人空间封面（16:9）文件 |
| `cover.standard_file` | 双图模式的首页推荐封面（4:3）文件 |

位置使用 `[水平百分比, 垂直百分比]` 表示最大内接裁剪框在可移动范围内的位置；某轴没有裁剪余量时该轴位置不产生作用。`[0, 0]` 为左上、`[50, 50]` 为居中、`[100, 100]` 为右下。用户可分别指定两种比例的位置，并在页面检查、调整最终构图。

### 4.5 其他投稿字段和设置

首版支持通过常规文本填写、选项选择和开关操作完成的投稿配置。各项范围如下：

| 分组 | 页面字段或设置 | 配置字段 | 用途 |
| --- | --- | --- | --- |
| 投稿信息 | 标题 | `info.title` | 稿件标题 |
| 投稿信息 | 创作声明 | `info.declaration` | 视频的内容性质声明，选项见下文 |
| 投稿信息 | 内容授权声明 | `info.no_reprint` | 是否声明“内容为自制：未经作者允许，禁止转载” |
| 投稿信息 | 分区 | `info.category` | 稿件所属分区 |
| 投稿信息 | 标签 | `info.tags` | 稿件的标签列表 |
| 投稿信息 | 参与话题 | `info.topic` | 希望参与的平台话题或活动 |
| 投稿信息 | 简介 | `info.description` | 稿件介绍，支持多行文本 |
| 发布与归档 | 定时发布开关 | `publish.scheduled` | 是否定时发布 |
| 发布与归档 | 定时发布时间 | `publish.at` | 期望的发布时间，包含时区 |
| 发布与归档 | 加入已有合集 | `publish.collection` | 希望加入的已有合集 |
| 展示设置 | 添加水印 | `display.watermark` | 是否添加水印 |
| 展示设置 | 可见范围 | `display.visibility` | `"公开可见"` 或 `"仅自己可见"` |
| 展示设置 | 在个人空间的投稿列表中隐藏 | `display.hide_from_profile` | 是否在个人空间隐藏稿件，与可见范围独立 |
| 商业信息 | 增加商业推广信息 | `commercial.enabled` | 是否开启页面中的商业推广信息选项 |
| 音视频设置 | 杜比音效 | `media.dolby_audio` | 是否开启杜比音效 |
| 音视频设置 | Hi-Res 无损音质 | `media.hires_audio` | 是否开启 Hi-Res 无损音质 |
| 音视频设置 | 全景视频 | `media.panorama` | 是否启用全景视频 |
| 互动设置 | 粉丝动态 | `interaction.dynamic` | 投稿动态文案，支持多行文本 |
| 互动设置 | 评论 | `interaction.comments` | 是否允许评论 |
| 互动设置 | 弹幕 | `interaction.danmaku` | 是否允许弹幕 |
| 互动设置 | 开启精选评论 | `interaction.selected_comments` | 是否开启精选评论 |
| 视频元素 | 个性化卡片 | 无 | 不纳入首版 |
| 视频元素 | 章节管理 | 无 | 不纳入首版 |

创作声明可选择：`"内容无需标注"`、`"含AI生成内容"`、`"含虚构演绎内容"`、`"内容含营销信息"`、`"个人观点，仅供参考"`、`"内容为转载"`。创作声明与内容授权声明分别配置，标签与参与话题分别配置。

开启定时发布时，用户提供期望时间；Bilipack 完成设置后仍由用户检查并提交。

### 4.6 字幕

- 字幕为可选附件，一个视频包可以提供多份字幕，每份分别指定文件和语言。
- Bilipack 上传配置中的各份字幕，并分别展示、核验结果。
- 未配置字幕时，保持页面已有字幕状态不变。

| 配置字段 | 用途 |
| --- | --- |
| `subtitles[].file` | 该份字幕文件的相对路径，首版支持 SRT |
| `subtitles[].language` | 该份字幕的语言，例如 `"中文"` |

配置使用 `[[subtitles]]` 表示字幕列表，每增加一份字幕就增加一个这样的区块。各份字幕用于添加或更新对应语言的字幕，未配置的语言保持原状。

### 4.7 用户编写示例

#### 最小视频包：从空白投稿页开始

```toml
[video]
file = "video.mp4"
```

该示例仅指定视频。其余字段沿用页面状态，平台必填项仍需用户补齐。

#### 常规投稿：单封面、文案、设置和字幕

下面展示各类常用字段的写法，示例值不是产品默认值。用户只需保留本次确实希望设置的项目。

```toml
[video]
file = "video.mp4"

[cover]
# mode 可省略，默认 single：同一原图分别适配两种比例。
mode = "single"
file = "cover.jpg"
wide_position = [50, 50]       # 16:9 居中
standard_position = [65, 50]   # 4:3 裁剪框向右移动

[info]
title = "我的视频标题"
description = """
第一段简介。

第二段简介，可以直接换行。
"""
category = "动画"
tags = ["动画", "创作分享"]
declaration = "内容无需标注"
no_reprint = true              # 仅适用于确实为自制且希望禁止转载的内容
# topic = "页面上的话题完整名称"

[publish]
scheduled = false
# collection = "我的已有合集名称"

[display]
visibility = "公开可见"
watermark = false
hide_from_profile = false

[commercial]
enabled = false

[media]
dolby_audio = false
hires_audio = false
panorama = false

[interaction]
dynamic = "这次分享我的创作过程。"
comments = true
danmaku = true
selected_comments = false

[[subtitles]]
file = "subtitles/zh.srt"
language = "中文"

[[subtitles]]
file = "subtitles/en.srt"
language = "英语"
```

#### 双封面与定时发布

使用双封面并希望定时发布时，可将上例中的 `[cover]` 和 `[publish]` 替换为以下内容。文件、时间及合集按实际需要填写。

```toml
[cover]
mode = "dual"
wide_file = "covers/16x9.jpg"
standard_file = "covers/4x3.jpg"

[publish]
scheduled = true
at = 2026-10-05T18:00:00+08:00
collection = "我的已有合集名称"
```

#### 已有视频：只修改简介和字幕

```toml
[info]
description = "修订后的简介。"

[[subtitles]]
file = "subtitles/修订版.srt"
language = "中文"
```

该配置不改变标题、封面、标签或其他未指定设置，也不重新上传视频。

## 5. 页面交互与执行规则

### 5.1 入口与浮窗

- 空白投稿页提供「使用 Bilipack 目录投稿」入口，已有视频的页面通过浮窗导入目录。
- 浮窗用于查看本次配置、附件和结果。
- 执行结束后提示结果，有未完成项时说明需要用户处理的内容。

### 5.2 先校验再操作

开始修改页面前，检查配置格式、引用文件及当前流程需要的输入。视频的必需性由页面是否已有视频决定。

### 5.3 以实际结果判断完成

- 每项填写后读回页面字段，确认实际值符合配置；执行结束后直接汇总各项结果，不再统一读回已核验项目。核验结论对应当时的页面状态，后续变化由用户最终检查。
- 附件以页面实际上传结果为准，不能仅凭选择文件或触发上传动作就认定完成。
- 视频上传百分比达到 100% 不单独作为完成依据，需确认页面明确显示上传完成。
- 对无法确认或不匹配的项目明确反馈，不能将其视为通过。

这里的“完成”指本次自动化准备和核验完成，不表示稿件已经提交、审核通过或公开可播放。

### 5.4 保留现场与人工提交

表单操作及逐项核验结束后，Bilipack 进入视频等待状态，此时页面操作已交还用户。无论用户留在表单页还是点击投稿进入平台等待页，Bilipack 都只观察并确认视频上传完成、保留已有结果，不再自动读回、修复或写入表单；任何再次写入都需用户明确发起。

失败时保留已填写内容和上传状态，供用户接手。自动化结束后由用户检查；Bilipack 不触发最终投稿或保存修改的提交动作。
