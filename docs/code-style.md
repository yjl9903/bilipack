# 编码规范

## 语言与命名

使用 strict TypeScript 和 ESM，公开 API 优先命名导出，入口保持精简。跨包通过包名导入，不引用另一 workspace 的源码。业务模块的相对导入通常不带扩展名；构建配置已有 `.ts` 导入时沿用所在文件的写法。

函数和变量用 camelCase，类型与 Vue 组件用 PascalCase，普通模块用简短且描述性的 kebab-case 名称。Vue 只负责 Bilipack 自有 UI；职责与依赖遵循 [模块规范](architecture/modules.md)。

## 实现约定

直接实现已确认需求，不为未确定能力增加扩展层。变更行为时同时检查类型契约、失败路径和 [测试规范](testing.md)，内部重构不得无意改变用户行为。保持配置缺省与显式空值、关闭值的区别；错误沿用结构化诊断和结果状态，不用提示文案决定业务行为。

平台写入通过适配器完成，并与能力检查、上下文绑定和读回配套。异步等待、监听、观察器及 Object URL 必须可清理；失败不能吞掉或伪装成功。注释解释约束和非显然的原因，不复述代码。

生成产物通过构建更新，不手工编辑 `dist/`。依赖变更同时维护 manifest 和锁文件，不混入无关修改。

## 格式

Prettier 使用两空格缩进、单引号、分号、无尾随逗号和 100 字符 print width。`pnpm format` 当前仅匹配 TS、JS、MJS，Vue、CSS、Markdown 和 JSON 保持现有格式并按需检查。当前无独立 lint 命令。

纯文档变更核对排版、链接和 `git diff --check`，不为文档修改批量格式化源码。
